## Track C, security fix, and the reviews that caught my own regressions

- **The finding that mattered was not in my plan.** A web-research pass against 2026 practice found that `encryptionService` returned a constant 32-byte key and a constant AES-GCM nonce whenever `process.env.JEST_WORKER_ID` was a string. Metro substitutes only dot-notation `process.env.NODE_ENV`, so the bracket-notation check and both weakened branches were compiled into the release bundle. Practically unreachable (nothing sets that variable on device), but it is a weak-crypto path in shipped code, and it meant the tests never exercised real key derivation or nonce randomness. Removed; tests drive the real path through the existing SecureStore mock. Lesson: making a test "real" by making production fake is the failure mode to look for when a suite looks well-covered.
- Same research corrected two things I was about to do. `icons/dnschat_ios26.png` is the 1024px store-listing asset, so the planned resize would have broken submission; only the bundled `src/assets` copy was resized. And virtualizing `GlassSettings`/`DNSLogViewer` would have nested a VirtualizedList inside a ScrollView, the documented anti-pattern, to virtualize a few fixed option groups. Dropped.
- **Two independent reviews then caught a regression I introduced.** Moving `endQuery`'s in-memory finalization out of the persistence queue means a query finishing while a `clearLogs` is queued is discarded by that clear, and my comment claimed ordering was unchanged. The obvious repair, clearing synchronously too, broke a tested guarantee that a failed storage removal must not report a deletion that never happened. The queued clear stays, the comment states the real trade, and a test pins the interleave. Lesson: when a fix makes an existing test fail, read what that test was protecting before deciding which side is wrong.
- Both reviews also rejected the crypto guard as a source-text grep, which `AGENTS.md` forbids as a substitute for behavior. Added a test that encrypts the same plaintext twice and asserts different nonces; it fails when a constant nonce is reinstated.
- The test-discovery floor I had set to 60 sat 51 files below the 111 that exist, so it could not fire. Replaced with a comparison against the specs actually on disk, verified against a nested spec a narrowed `testMatch` cannot see. A count is the wrong instrument for "did discovery break".
- **No device evidence for any of this.** The machine ran at loadavg 700+ for much of the session from other agents' builds, so wall-clock timing was meaningless throughout. Every performance change is proved by a work-count or ordering test instead: module-init counts, listener counts, render counts, and write-ordering. The one measured artifact is the earlier profiler baseline in `.scratch/perf/baseline-1/` (settings modal 123.9 ms across 91 components), which motivated the bottom-sheet change but was itself taken under load.
- Codex personal account hit its weekly limit mid-run and `codex exec` reported the error only inside the lane JSONL; the lane died having written real work to the tree with no final report. Recovering meant auditing the partial tree against the spec rather than trusting a summary.

## Autoreview verdict was wrong because it read the source, not the compiled output

P3 autoreview on the frontend commit returned three findings and "patch is incorrect (0.97)". Two of the three do not hold in a shipped build:

- It claimed `SafeMarkdown`'s `onLinkPress` is recreated per render, so the library's `AstRenderer` memo (which does depend on `onLinkPress`) still invalidates. A Jest probe agreed. Both were misleading: `jest.config.js` runs ts-jest, which does not apply the React Compiler, so nothing in the test environment is memoized. Running babel with `babel-preset-expo` plus `babel-plugin-react-compiler` over the real file shows `handleLinkPress` cached in a `$[3]` slot keyed on `t`, and `t` is itself compiler-memoized in `I18nProvider`. Stable in production.
- Same for `MessageList`'s `renderItem`: the compiled output caches it in `$[1]` keyed on `messageMaxWidthPx`.
- The third finding is correct and was kept: the `isPresented` early return sits after all of `GlassBottomSheet`'s hooks, so a closed sheet still allocates three animated values and a dimensions subscription. Only the modal subtree is skipped. The changelog now says exactly that instead of implying all three were avoided. Splitting the component into a gate plus an inner content component would fix it; not done at release time without device verification.

Lesson: for anything React Compiler touches, the reviewable artifact is the compiled output, not the source and not a ts-jest run. Two of three findings and the overall verdict came from reading source that the build rewrites.
